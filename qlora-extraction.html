index_engine

Rules-based equity index engine · Python, pytest

Overview

index_engine is a from-scratch equity index construction engine. It takes a universe of securities and produces index membership and weights under explicit, testable rules: periodic reconstitution, float-adjusted market-cap weighting, and banding/buffer rules that govern how names enter and leave the index. The whole pipeline is covered by a 17-test pytest suite so methodology changes are caught rather than assumed.

What it does

Reconstitution

On a defined schedule, the engine re-ranks the universe and rebuilds membership, mirroring how real index families are periodically reconstituted.

Float-adjusted market-cap weighting

Constituents are weighted by free-float-adjusted market capitalization rather than raw shares outstanding, reflecting investable size.

Banding & buffer rules

Membership uses hysteresis: a name has to clear an upper threshold to be added and fall below a lower threshold to be removed. The buffer between those edges is what suppresses churn from names hovering near the cutoff — the same idea the animation on the home page visualizes.

Headline finding — the banding study

The central experiment measures how the width of the band trades off against turnover. Turnover is the cost index methodology is built to manage: every add or drop is a transaction the tracking funds must make.

Widening the reconstitution band from 0% to 10% cut one-way turnover from 5.0% to 1.6% in a synthetic study — roughly a two-thirds reduction.

That result is the README centerpiece: a wider band meaningfully reduces churn, which is exactly the stability/responsiveness tradeoff an index designer has to reason about.

Testing

A 17-test pytest suite covers reconstitution logic, weighting math, and the banding state machine, so the engine's behavior is pinned down rather than incidental.
